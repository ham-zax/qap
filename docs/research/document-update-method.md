# Document Update Context Method

Use this before materially changing a long-lived QAP design, plan, research, or decision document.

1. **Recover context:** read the target doc plus the directly related decision/evidence/plan it depends on.
2. **State the update:** record a compact context note before editing: `Date | Trigger | Purpose | Decision impact | Evidence/links`.
3. **Preserve rationale:** update the current truth, but do not silently erase an old decision; mark it superseded when the reason still matters.
4. **Check consistency:** after editing, verify directly dependent docs/phase plans still agree and link to the authoritative detail instead of duplicating it.

Recommended note:

```text
Update context — YYYY-MM-DD
Trigger: <new evidence, decision, correction, or scope change>
Purpose: <why this document needs to change>
Impact: <what decision/plan changed; "none" if explanatory only>
Evidence: <source docs/issues/research/commits>
```

Keep the note short. The goal is provenance, not a changelog bureaucracy.
